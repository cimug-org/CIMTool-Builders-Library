# adoc-article-json.xsl

This builder currently ships with CIMTool.

## Builder Description

The **[adoc-article-json.xsl](adoc-article-json.xsl)** builder generates documentation for a JSON schema profile in [AsciiDoc](https://asciidoc.org/) format as a standalone article. The article has a title, a table of contents, the profile's class diagram and a section for each class, compound, enumeration and datatype, with tables of native and inherited members and cross-reference links between them. Text entered on the "Documentation" tab in CIMTool is included alongside the UML and profile descriptions.

The diagram is included from the ```<profile>.json-l2r.puml``` file generated by the [puml-json-l2r.xsl](../puml-json-l2r/builder.md) builder, so that builder should also be enabled for the profile. For content to embed within a larger AsciiDoc document use the [adoc-inline-json.xsl](../adoc-inline-json/builder.md) builder. Equivalent builders are provided for RDFS ([adoc-article-rdfs.xsl](../adoc-article-rdfs/builder.md), [adoc-inline-rdfs.xsl](../adoc-inline-rdfs/builder.md)) and XSD ([adoc-article-xsd.xsl](../adoc-article-xsd/builder.md), [adoc-inline-xsd.xsl](../adoc-inline-xsd/builder.md)) profiles.

## Builder NTE Configuration

Given this builder ships with CIMTool the below screenshot highlights the existing NTE (Name/Type/Extension) settings for the builder.  We strongly recommend that you do not import customized versions of this shipped builder over the original in your local CIMTool installation. Doing so will force regeneration of any existing builder-generated artifacts for projects in your workspace that have this builder enabled.

The recommended best practice is to rename the builder file  (from ```adoc-article-json.xsl``` to ```custom-adoc-article-json.xsl``` for example) before importing. On import this will be interpreted as a new builder and you will be allowed to enter values in the Type and Extension fields.

>*NOTE: </br>CIMTool requires that file extensions be unique and will prevent you from entering an extension already assigned to a builder. This is because an artifact's name is derived by concatenating the base name of the CIMTool ```.owl``` profile with the file extension assigned to the builder. Therefore, a unique file extension must be assigned to each builder when imported. The file extension for a builder can be modified later from within the "Maintain XSLT Transform Builders" screen.*
