# adoc-inline-rdfs.xsl

This builder currently ships with CIMTool.

## Builder Description

The **[adoc-inline-rdfs.xsl](adoc-inline-rdfs.xsl)** builder generates documentation for an RDFS profile in [AsciiDoc](https://asciidoc.org/) format as content to be included within a larger AsciiDoc document. The output has no document header, title or table of contents. It starts with a section for the profile and otherwise matches the [adoc-article-rdfs.xsl](../adoc-article-rdfs/builder.md) builder: the profile's class diagram and a section for each class, compound, enumeration and datatype, with tables of native and inherited members. Text entered on the "Documentation" tab in CIMTool is included alongside the UML and profile descriptions.

The diagram is included from the ```<profile>.rdfs-t2b.puml``` file generated by the [puml-rdfs-t2b.xsl](../puml-rdfs-t2b/builder.md) builder, so that builder should also be enabled for the profile. For a standalone document use the [adoc-article-rdfs.xsl](../adoc-article-rdfs/builder.md) builder. A variant with an additional mapping column is provided by the [adoc-inline-rdfs-mappings.xsl](../adoc-inline-rdfs-mappings/builder.md) builder. Equivalent builders are provided for XSD ([adoc-article-xsd.xsl](../adoc-article-xsd/builder.md), [adoc-inline-xsd.xsl](../adoc-inline-xsd/builder.md)) and JSON schema ([adoc-article-json.xsl](../adoc-article-json/builder.md), [adoc-inline-json.xsl](../adoc-inline-json/builder.md)) profiles.

## Builder NTE Configuration

Given this builder ships with CIMTool the below screenshot highlights the existing NTE (Name/Type/Extension) settings for the builder.  We strongly recommend that you do not import customized versions of this shipped builder over the original in your local CIMTool installation. Doing so will force regeneration of any existing builder-generated artifacts for projects in your workspace that have this builder enabled.

The recommended best practice is to rename the builder file  (from ```adoc-inline-rdfs.xsl``` to ```custom-adoc-inline-rdfs.xsl``` for example) before importing. On import this will be interpreted as a new builder and you will be allowed to enter values in the Type and Extension fields.

>*NOTE: </br>CIMTool requires that file extensions be unique and will prevent you from entering an extension already assigned to a builder. This is because an artifact's name is derived by concatenating the base name of the CIMTool ```.owl``` profile with the file extension assigned to the builder. Therefore, a unique file extension must be assigned to each builder when imported. The file extension for a builder can be modified later from within the "Maintain XSLT Transform Builders" screen.*
